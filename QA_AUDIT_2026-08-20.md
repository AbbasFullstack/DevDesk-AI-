# DevDesk AI — Five-Pass Production QA Audit

## Pass 1 — Public landing and authentication entry

The live public landing page loaded successfully at `https://dev-desk-ai-phi.vercel.app`. Its branded logo, navigation links, public workflow sections, source-security copy, and both Sign in entry points were visible. The header Sign in control opened an authentication panel containing an email input, password input, Sign in action, and Sign up action.

**Result:** Pass 1 public entry flow is functioning at the observed desktop viewport. Authenticated feature verification remains pending.

## Pass 2 — Authentication and protected workspace entry

A dedicated temporary QA account was registered through the live Sign up form. The live site established an authenticated workspace session immediately and displayed the protected workspace shell, developer navigation, account identity, repository control, composer controls, and AI-online indicator.

**Result:** Pass 2 authentication and protected workspace entry passed. This temporary QA account is used only for this audit and must be removed during audit cleanup.

## Pass 3 — Authenticated workspace and chat routing

The authenticated workspace rendered all expected controls: workspace navigation, Projects, Analyses, Connectors, account menu, GitHub connect/repository controls, project entry, prompt dictation, media tools, chat composer, and send action. A production chat request asking about React effect cleanup completed successfully with a coherent server-side AI response; no busy error or client-side rendering failure occurred.

**Result:** Pass 3 workspace and normal chat routing passed.

## Pass 4 — Image Generation entry and progress UI

The authenticated composer’s media trigger opened successfully. Both Voice Call and Image Generation actions were visible. The Image Generation action opened a form with a bounded prompt textarea, all five supported aspect-ratio choices, and a Generate action.

**Result:** Image Generation entry and form controls passed. A real provider request is the next Pass 4 step.

The real authenticated image request started successfully. The Generate button entered its creating state and the new live status feedback appeared during the request, including a continuously advancing percentage indicator and the message “Creating with the free AI image model…”.

The request then reached the later-stage fallback status, “Still working — checking the backup free model if needed…”, at 88%. The UI remained responsive and did not expose a raw upstream failure while the bounded fallback interval was still active.

Both server-side free image attempts ultimately failed in this live authenticated test. The UI correctly recovered to a retryable state, showing “Generation paused — you can retry now” and the safe error “Free image models are temporarily busy. Please retry in a moment.” This is a real availability defect because no image result was produced.

**Result:** The Image Generation UX feedback passed, but end-to-end availability failed. A third, no-key fallback path is required before Pass 4 can pass.

## Pass 5 — Voice Call page and device controls

The dedicated Voice Call page loaded from the authenticated media panel with its back navigation, settings trigger, mute control, Start voice call action, and Test voice action. Its settings panel exposed Auto/device, Urdu, English (US), English (UK), Hindi, and Arabic language choices plus all six requested voice-style controls: Girl, Boy, Woman, Man, Adult, and Senior.

The sandbox browser reports no installed SpeechSynthesis voices, so its device-voice selector correctly displayed “No matching voice installed.” This environment cannot be used to judge audible output, but it can still validate the application’s capability handling and visible recovery feedback.

The Test voice action returned a precise media-volume recovery message in the no-voice sandbox browser. Starting the call transitioned the visible state to connected, attempted recognition, and then surfaced the specific microphone-permission recovery message: “Microphone is blocked. Allow mic permission in Chrome settings, then tap the mic.” No unhandled errors or page crashes occurred.

**Result:** Voice Call UI, language/style settings, lifecycle states, and browser capability recovery feedback passed. Real audible speech and microphone capture remain device-specific checks for the Galaxy A21s because the QA browser has neither installed voices nor microphone permission.

## Pass 4 retest — Final image fallback

After deployment, the same authenticated image request again completed both Vercel-side free-provider attempts. The final browser-delivery URL was returned, but the browser image load failed and the application showed its safe recovery state: “Backup image delivery could not load — please retry.”

**Result:** The first final-fallback implementation did not resolve end-to-end image availability. The audit remains open while the browser-load failure is diagnosed and replaced.

### Root cause and repair

The image URL builder was passing full millisecond timestamps as provider seeds. The direct provider probe succeeded with a bounded seed, while the production path consistently failed with timestamp-sized values. Image seeds are now normalized to a positive 32-bit-safe integer before every Sana, Flux, or browser-delivery URL is built. The regression is covered by deterministic tests.
